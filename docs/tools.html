Tools for LLMs

Every tool an agent can call, as the kit defines it. Get them in your model's format with kit.tools.openai(names?) or kit.tools.anthropic(names?), and run one with await kit.tool(name, args). Tools from a feature appear once the feature is loaded; calling one loads it. These definitions are read from the running kit, so they match v3.0.0.

Built in

read#

Read a text file. Lines are numbered (cat -n style). Use offset (1-based line) and limit for long files.

ArgumentTypeDescription
path requiredstringfile path, e.g. /notes/todo.md
offsetintegerfirst line to read (1-based)
limitintegernumber of lines (default 2000)

write#

Create or overwrite a file with the given content (folders are created as needed).

ArgumentTypeDescription
path requiredstring
content requiredstring

edit#

Edit a file by replacing exact text. oldText must match the file exactly (whitespace included) and occur once, unless replaceAll is true. Read the file first.

ArgumentTypeDescription
path requiredstring
oldText requiredstringthe exact text to replace
newText requiredstringthe replacement
replaceAllboolean

bash#

Run a shell command line (BusyBox: ls, cat, grep, sed, awk, find, …; pipes, redirects, && ||, $(…)). Also node, python and sqlite3. The working directory persists between calls.

ArgumentTypeDescription
command requiredstring
timeoutintegerseconds (default 60)

python#

Run MicroPython code. The file system is shared with the other tools. print() output is returned.

ArgumentTypeDescription
code requiredstring

javascript#

Run JavaScript in a Node-style sandbox (require fs, path, node:sqlite; fetch). console.log output is returned, and the value of a top-level return.

ArgumentTypeDescription
code requiredstring

sqlite#

Run SQL on a SQLite database file (created if missing; ":memory:" for a scratch one). sqlite-vec (vec0, vec_distance_cosine) and FTS5 are built in. Returns rows as JSON.

ArgumentTypeDescription
database requiredstringfile path, e.g. /data/app.db
sql requiredstring
paramsarray of any

search_files#

Find files by meaning of words (BM25 ranking) under a folder. Returns paths, scores and a snippet.

ArgumentTypeDescription
query requiredstring
pathstringfolder (default /)
limitinteger

search#

Search the web (Ollama web search). Returns titles, URLs and text snippets.

ArgumentTypeDescription
query requiredstring
max_resultsinteger1-10 (default 5)

fetch#

Fetch a web page by URL (Ollama web fetch). Returns its title, text content and links.

ArgumentTypeDescription
url requiredstring

decide#

Ask a decision model to judge something with calibrated probabilities: pick one option (choice), rate on levels (score), or answer yes/no (yesno). Fast and cheap; use it for triage, routing and checks.

ArgumentTypeDescription
state requiredstringwhat to judge: a message, log, diff, error or JSON
question requiredstringwhat to decide, as an instruction
typechoice | score | yesno
optionsarray of stringchoice: the options; score: 2-10 levels, lowest first; yesno: none

tasks#

Your task list for multi-step work: add tasks when you plan, mark one in_progress while you work on it and done when it is finished. Actions: add (title, or titles for several), update (id, status, title, notes), list, remove (id), clear (removes done tasks).

ArgumentTypeDescription
action requiredadd | update | list | remove | clear
titlestring
titlesarray of string
idinteger
statuspending | in_progress | done
notesstring

schedule#

Schedule work to run later or repeatedly while the page is open: a shell command, JavaScript, Python, or a prompt for an agent. "when" is plain English ("every day at 9am", "weekdays at 8:30", "every 30 minutes", "in 20 minutes", "tomorrow at 7pm") or 5-field cron. Actions: add, list, remove, enable, disable, run (now).

ArgumentTypeDescription
action requiredadd | list | remove | enable | disable | run
namestring
whenstring
commandstringa shell command line
jsstring
pythonstring
promptstringa prompt for an agent
idstringjob id or name

sentry#

Sentry: rules that watch the page and its sensors and act when something happens. Actions: systems (what can be watched), list, add (rule), remove (id), enable / disable (id), status (current readings and rules), emit (event name + data), set (key + value). A rule: { id, when: {src, op: lt|le|gt|ge|eq|ne|in, value} (or all/any/not, or {src:"geo", op:"inside"|"outside", lat, lon, radius_m}), on: {event, where}, for_s, cooldown_s, hours: "22:00-07:00", alert: {notify}, run: {command | js | python | prompt | tool} }.

ArgumentTypeDescription
action requiredsystems | list | add | remove | enable | disable | status | emit | set
ruleobject
idstring
eventstring
dataobject
keystring
value

From delegate

delegate#

Hand a self-contained side job to a sub-agent with its own clean context; it returns only a short report, so raw pages and search results do not fill your context. It cannot see this chat: give the full task and what the answer must contain. Read-only unless write: true; no nesting.

ArgumentTypeDescription
task requiredstring
contextstringbackground it needs
writebooleanallow write, edit, bash, python, javascript, sqlite
max_stepsinteger
secondsinteger

From secrets

The names of the secrets (API keys, tokens) the app has given you. You never see their values: use them as {{ secrets.NAME }} in playbooks and http requests.

From flows

flow#

Automation flows (like n8n): steps that run in order — tools, JavaScript, shell, decisions, model answers, agent runs, files, if / switch / for-each, wait, notify, playbooks, other flows. A flow runs by hand, on a schedule or when a file changes. Actions: help (the format and every step type: read it first), list, get, create, update, delete, run, runs, enable, disable.

ArgumentTypeDescription
action requiredhelp | list | get | create | update | delete | run | runs | enable | disable
namestring
flowobjectcreate / update: the whole flow (see help)
inputrun: input ($input and the first $json)
limitinteger

playbook#

Deterministic automation without the model, like Ansible in JSON: a saved list of tasks that call tools, with variables and when/loop/register/retries/rescue. Save once (the app approves it), run exactly the same way any time, also from flows, schedules and the queue. action help prints the format.

ArgumentTypeDescription
action requiredhelp | modules | save | run | plan | list | show | validate | delete
namestring
playbookobject{description, vars, allow_hosts, tasks}
varsobject
tagsarray of string
secondsinteger

From http

http#

Make an HTTP request to an API (GET, POST, PUT, PATCH, DELETE, HEAD, OPTIONS). Use secrets as {{NAME}} in url, query, headers or body (the secrets tool lists them); you never see their values. json: a body sent as JSON; form: a form body.
